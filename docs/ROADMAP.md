# 开发路线图

路线图描述可能的后续阶段，不承诺具体发布日期。

## 阶段一：稳定本地工作流

- 完善真实台本库和编辑器的边界状态、恢复和错误提示。
- 补充 Android 设备、横竖屏、字体缩放和输入法矩阵测试。
- 完善无障碍语义、TalkBack 和大字体布局。

## 阶段二：文件导入

- ✅ TXT 导入：系统文件选择器、UTF-8/UTF-16/GB18030 编码识别、5 MiB 大小限制。
- ✅ DOCX 导入：OOXML 直接解析，只提取普通正文段落；样式、表格、图片、目录、字段等结构跳过。
- ✅ DOC 导入：OLE2 二进制解析，只提取普通正文段落；表格段落与字段结果跳过。
- ✅ Markdown 导入（纯文字子集）：一级标题作为台本标题、其他标题转为正文段落、空行分段；粗体/斜体/列表/代码/链接/表格/HTML 等特殊格式拒绝导入，5 MiB 限制。
- 扩展 Markdown 子集：有序/无序列表、粗体/斜体、行内代码、引用等（当前不规划）。
- 增加批量导入、原文件复制或持续关联等可选能力（当前不规划）。

## 阶段三：播放稳定性

- 进行长时间播放、掉帧、Activity 重建和方向切换压力测试。
- 完善播放 Session 快照、恢复策略和更多设备 Insets 组合。
- 增加截图/布局回归和现场使用诊断信息。

## 阶段四：局域网控制端

- ✅ 已完成远控基础架构：领域模型、协议消息、Session Repository、可注入的 Transport、控制端 UI 与业务状态解耦、提词端状态快照与控制命令协调层。
- ✅ 已完成真实一对一局域网 WebSocket：提词端 Server + 控制端 Client、一次性二维码配对与握手、单控制端限制、心跳、断线重连（有限指数退避）、状态快照同步（250 ms 节流 + revision 乱序过滤）、真实播放命令，并接入 Setup 保存后启动。
- 进行双设备人工实测（手机热点、同一 Wi-Fi 两个场景），验证扫码、配对、控制、断线续播和自动重连的完整闭环。
- 多控制端/一对多、局域网自动发现（mDNS/NSD）、公网连接。
- 升级 `targetSdk 37` 后适配局域网运行时权限。

## 阶段五：多设备与语音研究

- 评估一对多控制和多台提词端扩展。
- 研究逐词位置、语音跟随和语速自适应。
- 根据稳定性和隐私要求评估是否需要可选云同步。

## 发布准备

- 建立真实 CI 构建和测试检查。
- 完善隐私说明、正式截图、测试版本说明和崩溃反馈流程。
- 在功能和设备矩阵达到可接受稳定性后，再准备首个测试版本。
