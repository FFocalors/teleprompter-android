# 开发路线图

路线图描述可能的后续阶段，不承诺具体发布日期。

## 阶段一：稳定本地工作流

- 完善真实台本库和编辑器的边界状态、恢复和错误提示。
- 补充 Android 设备、横竖屏、字体缩放和输入法矩阵测试。
- 完善无障碍语义、TalkBack 和大字体布局。

## 阶段二：文件导入

- ✅ TXT 导入：系统文件选择器、UTF-8/UTF-16/GB18030 编码识别、5 MiB 大小限制。
- ✅ DOCX 导入：OOXML 直接解析，保留粗体/斜体/下划线、表格和超链接显示文字。
- ✅ DOC 导入：OLE2 二进制解析，优先保证正文与段落完整，格式有限降级。
- ✅ Markdown 导入（纯文字子集）：一级标题作为台本标题、其他标题转为正文段落、空行分段；粗体/斜体/列表/代码/链接/表格/HTML 等特殊格式拒绝导入，5 MiB 限制。
- 扩展 Markdown 子集：有序/无序列表、粗体/斜体、行内代码、引用等（当前不规划）。
- 增加批量导入、原文件复制或持续关联等可选能力（当前不规划）。

## 阶段三：播放稳定性

- 进行长时间播放、掉帧、Activity 重建和方向切换压力测试。
- 完善播放 Session 快照、恢复策略和更多设备 Insets 组合。
- 增加截图/布局回归和现场使用诊断信息。

## 阶段四：局域网控制端

- 实现一对一设备发现、二维码配对和安全连接。
- 同步台本、准备状态、播放位置、速度和暂停/恢复事件。
- 在现有 UI 状态和事件接口基础上替换本地 Mock Session。

## 阶段五：多设备与语音研究

- 评估一对多控制和多台提词端扩展。
- 研究逐词位置、语音跟随和语速自适应。
- 根据稳定性和隐私要求评估是否需要可选云同步。

## 发布准备

- 建立真实 CI 构建和测试检查。
- 完善隐私说明、正式截图、测试版本说明和崩溃反馈流程。
- 在功能和设备矩阵达到可接受稳定性后，再准备首个测试版本。
